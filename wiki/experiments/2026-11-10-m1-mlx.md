# M1 MLX GPU verification after macOS upgrade

**Measured locally:** M1 MacBook Air, 8 GiB RAM, native arm64 Python 3.12.0,
macOS 27.2.1, MLX and mlx-metal 0.32.4 in the project virtual environment.
Free disk was approximately 28 GiB. OS and disk blockers from the
[initial preflight](2026-11-10-m1-preflight.md) have cleared.

An explicit GPU float32 16×16 matrix product and sum returned 4096.0, with a
256 MiB MLX budget and 32 MiB cache limit. The two existing MLX-versus-CPU tests
passed with hardware enabled, no skips: forward loss and one SGD update for
the default and two-layer small models. See the [commands, raw result and test
output](../../evidence/m1-mlx-2026-11-10/README.md). No numerical tolerances were
changed. The virtual environment still inherits system-site packages; it is
not a full `uv.lock` accelerator environment.

**Limits:** no Qwen3 weights/data were downloaded, no QLoRA run occurred, and
ANE availability, correctness, and residency remain unverified. No throughput,
power, large-model fit, or multi-step stability claim follows from these tests.
No system memory or security setting changed.

**Still blocked:** GPU QLoRA needs mlx-lm 0.32.2 and mactop; hybrid QLoRA also
needs ANEForge 0.4.0. ANE-only Qwen3 is unimplemented. The 15 GiB disk admission
reserve can remain unchanged. [M1 workflow](../../configs/M1_8GB/README.md),
[GPU validation guide](../guides/mlx-validation.md), [state](../project/state.md).
