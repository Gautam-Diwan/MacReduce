## Findings

- MLX ships tensor-parallel building blocks in `mlx.nn`: `AllToShardedLinear` shards weights along the output dimension and does not gather; `ShardedToAllLinear` shards along the input dimension and all-reduces with `all_sum`. Quantized variants exist and are frozen (no gradients). `shard_linear` converts an existing layer.
- Combined with [S02](S02.md), which states JACCL is "necessary for things like tensor parallelism", Apple's own stack covers tensor-parallel inference across Thunderbolt-connected Macs. Pipeline parallelism is not described on this page or on S02; the term appears in the EXO README ([S18](S18.md)) as a sharding option.

## Limitations

Documentation describes capability, not measured speedup on any specific Macs. No ANE or CPU placement is discussed; the examples assume one GPU per rank.

## What this source blocks

- "Connect Macs for inference with tensor parallelism" is covered by first-party code. MacReduce should not build collectives or sharded layers.
