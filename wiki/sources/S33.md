## Findings (issue text, not reproduced)

- **#1446 (open, 2026-07-01):** `mlx_lm.server` with a Qwen3.6-35B-A3B MoE target and a Qwen3.5-0.8B draft fails with `ValueError: Speculative decoding requires a trimmable prompt cache (got {'ArraysCache'})` on mlx-lm 0.31.3 / mlx 0.31.2, macOS 26.0. Baseline generation without the draft works.
- **#1423 (open, 2026-06-21):** greedy speculative output diverges from greedy non-speculative output for gemma-4-31b-it-8bit with a gemma-4-e2b-it-4bit draft on an M3 Ultra, mlx-lm 0.31.3. The reporter states it is reproducible and deterministic.
- **#846 (open, 2026-02-05):** Qwen3-Next-80B with Qwen3-0.6B drafts skipped tokens (counting 1–20 produced 1,3,5,6,8,...) on mlx-lm 0.30.4 regardless of draft quantization; workaround was to disable the draft. A later PR title (#1111) claims to fix speculative decoding for hybrid models and references #846.
- **#1914 (closed same day, 2026-09-23):** `RotatingKVCache._update_concat` computed trim size assuming one token per call, so sliding-window models (Gemma 3/4) took a different cache path under speculative verification than under plain decode and the window silently grew.
- Other titles indicate active churn: native MTP speculative decoding, DFlash block diffusion, prompt-lookup decoding, an "auto-speculative router", and warnings that speculative decoding may hurt MoE throughput (#1313, #1132).

## Limitations of this reading

Issue reports describe user environments; none were reproduced here. Open status was read on 2026-10-25 and may change. This is not a complete audit of mlx-lm.

## What this source blocks and what it opens

- It blocks treating stock MLX speculative decoding as a stable baseline across model families; any MacReduce experiment must pin mlx-lm and mlx versions and verify greedy equivalence first.
- It supports the claim that **cache compatibility and cache-path divergence are real failure modes** when drafts and targets, or prefill and decode, are produced by different code paths. That is directly relevant to any cross-engine (ANE/GPU) or cross-machine handoff.
