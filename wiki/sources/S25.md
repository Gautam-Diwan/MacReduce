## Findings

- The repository benchmarks five strategies for Qwen3.5 on an **M2 Ultra, 192 GB**: MLX GPU; CoreML prefill plus MLX GPU decode; ANE-LM private-API sequential prefill and decode; ANE-LM prefill plus GPU decode; and ANE-LM batch prefill (32 tokens) plus GPU decode.
- Source-reported TTFT for Qwen3.5-0.8B on a 410-token prompt: MLX GPU 96 ms; CoreML hybrid 100 ms; ANE-LM sequential 17,831 ms; ANE-LM batch about 276 ms. For Qwen3.5-9B 8-bit the CoreML hybrid showed "no crossover point" and was 2.0x to 8.2x slower than GPU.
- A central finding the source states: on macOS 26.3, CoreML `compute_units=ALL` **routed to the GPU, not the ANE** (measured ANE power about 0 W), so the "hybrid ANE" CoreML rows actually compare CoreML-GPU with MLX-GPU. `CPU_AND_NE` was reported to cause an ANE IPC deadlock.
- Source-reported: genuine ANE batch dispatch via private API reaches 268 tok/s prefill for 0.8B, 11.3x over sequential; ANE prefill reduced GPU power from 62.05 W to 0.22 W. Single-token ANE dispatch latency is reported as about 42 ms per token regardless of model size.
- ANE-LM and MLX use **incompatible KV-cache formats**; the ANE-LM hybrid rows are therefore composed from separately measured phases, not an end-to-end run. The CoreML path needs a cache bridge and a mixed-precision bridge cost 11–16% decode throughput on 9B.
- First-load CoreML compilation is reported at about 2 minutes for seq64 up to about 97 minutes for seq512.

## Limitations of this reading

README only; the hardware is an M2 Ultra, not the project's M4; macOS 26.3, not 26.5. Numbers are the maintainers' and not reproduced here.

## What this source blocks

- "ANE prefill plus GPU decode on one Mac" is already benchmarked, including negative results. A MacReduce contribution cannot be the handoff itself.
- It establishes that **compute-unit selection within Core ML is not reliably an ANE placement**, which any scheduler that treats "ANE" as a resource must verify with power or counters, not flags. See [S36](S36.md).
- It leaves open: a policy that decides per request whether to use the ANE path given prompt length, model size, compile state, and cache-bridge cost. The source gives fixed tables, not a decision procedure.
