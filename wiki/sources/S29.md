## Findings

- laya-apple runs the Laya typed-decision model (a single-forward-pass classifier-style model, not an autoregressive LLM) on **MLX GPU and the ANE concurrently** and routes each request to one engine. Routing rule, source-reported for one M4 Max: one question and ≤128 tokens with a validated ANE artifact go to the ANE (9.9 ms versus 12.2 ms on MLX at L128); longer or multi-question requests stay on the GPU (MLX 19.2 ms at L256, 71.0 ms at L1024). Under load it also compares queue backlogs.
- The headline numbers the user cited are in the v1.0 table: throughput versus GPU-only **2.92x (laya), 4.34x (laya-multilingual), 4.57x (laya-typed-decisions)**; short-request P99 for typed-decisions **1592.9 ms GPU-only versus 79.5 ms GPU+ANE**. Hardware: one Apple M4 Max; workload: a short and a long request stream under open-loop bursty load, so queueing counts. The README itself says "the gain comes from running both engines at once, not from raw ANE speed." The later Switchyard benchmark reports P99 3,107–3,170 ms GPU-only versus 54.5–54.7 ms GPU+ANE on macOS 26.6.2.
- Correctness: a plain Core ML export with `CPU_AND_NE` produced 12–85 hard mismatches against upstream; laya-apple only uses an ANE artifact after a per-machine FP16 parity gate (probability error ≤0.02, 0 hard mismatches). Explicit ANE requests raise rather than fall back; every result records `device` and `routing_reason`.
- Costs stated: Core ML first-load compile of 3–5 minutes per model (273.5 s cold versus 2.7 s warm in one run); compile cache grows 0.7–1.4 GB per bucket without eviction; the synchronous Core ML call holds the GIL, which motivated an asynchronous path with a breaker that falls back on slowdown.
- Limitations stated: one test machine (M4 Max); prebuilt artifacts only for M4 Max with coremltools 9.0 on macOS 26/27; ANE path is batch 1; routing thresholds "are not assumed to hold on other Apple SoCs".

## Limitations of this reading

README only. The model is a short-context classifier; nothing here measures LLM prefill or decode. All numbers are project-reported from one M4 Max and are not reproduced on MacReduce's M4.

## What this source blocks

- "Concurrent GPU + ANE serving with per-request routing on a Mac" exists, including explained routing, a parity gate, and no-silent-fallback semantics. A MacReduce router for a classifier workload would duplicate this.
- Its thresholds are static per-platform calibrations ("calibrate" command). It does not learn online, does not consider a second machine, and does not cover autoregressive decode. Those remain open in this source, though not necessarily elsewhere.
