## Findings

- Hypura is described as "a storage-tier-aware LLM inference scheduler for Apple Silicon" that places tensors across **GPU, RAM, and NVMe** tiers using a hardware profile (GPU working set, RAM, NVMe bandwidth) and an "LP + greedy" placement solver. It wraps llama.cpp (vendored) and reads GGUF.
- Three modes are chosen automatically: full-resident, MoE expert-streaming (router interception, neuron cache with a reported 99.5% hit rate, co-activation prefetch), and dense FFN-streaming.
- Source-reported numbers on an M1 Max 32 GB with ~5.1 GB/s NVMe: Qwen 2.5 14B Q4_K_M 21 tok/s (same as llama.cpp); Mixtral 8x7B Q5_K_M 2.2 tok/s where llama.cpp OOMs; Llama 3.3 70B Q4_K_M 0.3 tok/s where llama.cpp OOMs.
- The author states the code was produced by directing LLMs and that it is an exploration, not a product.

## Limitations of this reading

README only. The scheduler operates **within one machine** and over **memory tiers**, not across machines or compute engines; CPU/GPU/ANE engine choice is not a decision it makes. No TTFT numbers.

## What this source blocks

- "Memory-tier-aware placement on a Mac" is existing work, including an automatic profile-then-solve step. A MacReduce scheduler that only chooses where weights live would be a reimplementation.
- Useful as a design pattern: profile once, cache, solve placement, expose `inspect` to show the plan before loading.
