## Findings

- A second, independent prefill/decode split: a GB10 Spark prefills, a **Mac Studio M3 Ultra 256 GB** decodes Qwen3.8 Flash Next (hybrid linear/sparse attention with an MTP head), with state moved over **RDMA through a ConnectX-5 in a Thunderbolt 5 enclosure**. The README calls it "not a product": macOS 27.2 beta, SIP off, patched driver, fork branches.
- Source-reported (24 runs per setup, 500 to 64k prompt tokens): the split wins on code at long prompts (from about 32k tokens); a single Spark with TensorFold wins on shorter code prompts and gives first token 2–5 s sooner on prose; Mac alone decodes as fast as the split but prefills at 700–850 tok/s. The KV handoff adds 0.35–1.9 s of transfer at about 8.5 Gbit/s plus about 1.7 s setup.

## Limitations of this reading

README only. Exotic hardware and a beta OS; not reproducible by this project.

## What this source blocks

- Together with [S30](S30.md), it shows that the crossover for disaggregation depends on workload type (prose versus code), prompt length, and the single-machine alternative's drafting speed. Two published tables disagree on where the split wins, which is itself the argument for a decision procedure rather than another table.
