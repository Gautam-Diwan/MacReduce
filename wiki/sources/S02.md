MLX provides distributed communication facilities and backend-specific setup. This is a baseline to inspect before building optimized collectives. Availability and network behavior depend on backend and environment; documentation alone does not establish Wi-Fi scaling or ANE execution. MacReduce currently uses its own small HTTP protocol, not these collectives.

## Re-reading 2026-10-25

**Scope:** the main text from "Distributed Communication" through "Getting Started with JACCL", plus the headings list, read from the saved snapshot. The page is the MLX 0.32.4 build, matching the locally installed version.

- Backends table: MPI; RING ("ring all reduce and all gather over TCP sockets. Always available and usually faster than MPI"); JACCL ("low latency communication with RDMA over thunderbolt. Necessary for things like tensor parallelism"); NCCL for CUDA. `init(backend="any")` tries all and falls back to a singleton group.
- JACCL: "Starting from macOS 26.2, RDMA over thunderbolt is available and enables low-latency communication between Macs with thunderbolt 5," with latency "an order of magnitude lower than the ring backend." Setup needs `mlx.distributed_config`, a full Thunderbolt mesh, and optionally password-less sudo.
- The ring backend's "main purpose is to use Thunderbolt rings"; it also works over Ethernet or any reachable IP, which includes Wi-Fi, though Wi-Fi is mentioned only as the ssh path for configuration.
- The page links two example pages, Data Parallelism and Tensor Parallelism, now saved as [S35](S35.md) and [S34](S34.md). The page does not describe pipeline parallelism or any prefill/decode notes; the "Tips and Tricks" section advises batching communication because many small transfers hurt.

**Uploaded copy:** `distributed-0.html` supplied on 2026-10-25 is a text rendering of this same 0.32.4 page (same sentences and headings, 39,367 bytes versus 171,607 for the HTML snapshot). It was not intaken as a new source and these bytes were not modified.

**Consequence:** connecting Macs, including Thunderbolt RDMA, is covered by first-party code. MacReduce should not build collectives ([decision 0003](../decisions/0003-build-target.md)). JACCL requires macOS 26.2+ and Thunderbolt 5 hardware that this project has not confirmed it has.
