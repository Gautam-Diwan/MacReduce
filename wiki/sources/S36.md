## Findings

- `compute_units` takes `CPU_ONLY`, `CPU_AND_GPU`, `CPU_AND_NE`, or `ALL` (default). The documentation states the default "uses all compute units available" and that defaults are "picked to execute the model in the most performant way". The parameter is a **constraint on which units Core ML may use**, applied at model load; it is not a guarantee that a given op or model runs on the Neural Engine.
- This is the distinction the project needs: Core ML's compute-unit selection is **within-model placement decided by Apple's runtime**; a cluster or cross-engine scheduler is a different layer that decides which *model instance* or *phase* runs where, and must verify the runtime's actual placement with counters or power, as [S25](S25.md) and [S29](S29.md) found necessary.

## What this source blocks

- "Choose ANE versus GPU with a flag" is not a scheduler. Any MacReduce claim about ANE use must be backed by a placement check (compute plan, power, or a parity-gated private-API path), never by the flag value alone.
