## Re-reading 2026-10-25

**Scope:** the first 120 lines of the snapshot plus a keyword scan of the rest. The README on `main` fetched 2026-10-25 was byte-identical to this snapshot (SHA-256 match), so no new source ID was needed. GitHub API metadata the same day: `exo-explore/exo` is **not archived**, last push 2026-10-13, Apache-2.0, and the README names no successor project.

- Features stated: automatic device discovery; "day-0 support for RDMA over Thunderbolt 5"; "topology-aware auto parallel" based on device resources and link latency/bandwidth; tensor parallelism with "up to 1.8x speedup on 2 devices and 3.2x on 4"; MLX as the inference backend and MLX distributed for communication; OpenAI, Claude, Responses, and Ollama API compatibility; a dashboard. The macOS app needs macOS 26.2+.
- The snapshot's configuration text lists `"sharding": "Pipeline"` and a `--sharding` filter with `pipeline`, `tensor`, or `both`, so pipeline sharding is a supported mode per the README.
- Benchmarks shown are third-party images from a 4x M3 Ultra 512 GB cluster; none were reproduced.

**Consequence:** the cluster-inference layer across Macs, including placement by topology, is occupied. MacReduce does not build another EXO ([decision 0003](../decisions/0003-build-target.md)). EXO does not, per its README, choose between CPU, GPU, and ANE engines within a machine or make per-request speculation or prefix decisions; that is a reading of the README, not an audit of the code.
